# GAALI: A Pilot Benchmark for Offensive Language Detection in Romanized Code-Mixed Nepali

Dataset, model training, statistical evaluation, and manuscript code accompanying
*GAALI: A Pilot Benchmark for Offensive Language Detection in Romanized Code-Mixed Nepali*.
Every number reported in the paper is regenerated by the four scripts in `analysis/`, run
in filename order.

## Layout

```
data/                        stratified corpus + per-instance test predictions
  corrected_cleaned_combined_data_kaggle_stratified.csv
  test_set_model_predictions.csv
training/                    model training pipeline
  train_models.py            main experiment: TF-IDF (SVC, MNB) + Transformers (mBERT, XLM-R, MuRIL, IndicBERT)
  train_indicbert.py         standalone IndicBERT run with gated Hugging Face Hub login
analysis/                    produces every number and table in the paper
  00_audit.py                corpus integrity, split balance, near-duplicate audit
  01_benchmark.py            Tables 3, 4 and 6
  02_ablation.py             Table 5, the dhoti denominators, leakage thresholds
  03_subgroup_leakage.py     Tables 7 and 8, error-overlap statistics
  stat_reliability.py        reusable bootstrap + McNemar CLI (not needed for the paper)
exploratory/                 analyses that informed the paper but are not reported in it
manuscript/                  regenerates the submitted .docx
```

## Data

The two benchmark files are included in `data/`:

| File | Rows | Columns |
|---|---:|---|
| `corrected_cleaned_combined_data_kaggle_stratified.csv` | 6,773 | `Comment`, `Label` (`1` = offensive, `0` = non-offensive), `split` (`train` = 5,418 / `dev` = 677 / `test` = 678) |
| `test_set_model_predictions.csv` | 678 | `Comment`, `true_label`, `svc_pred`, `mnb_pred`, `mbert_pred`, `xlm_roberta_pred`, `muril_pred`, `indicbert_pred` |

Rows in `test_set_model_predictions.csv` are in the exact same order as the
`split == 'test'` rows of the corpus file; `01_benchmark.py` asserts this on startup.

To read data from an external directory instead, set `GAALI_DATA_DIR`:

```bash
export GAALI_DATA_DIR=/path/to/data
```

## Install and run

### 1. Reproduce all paper tables and statistical tests (from included predictions)

```bash
pip install -r requirements.txt
cd analysis
python 00_audit.py            # integrity and leakage audit
python 01_benchmark.py        # Tables 3, 4, 6  -> metrics_final.csv, pairwise_final.csv
python 02_ablation.py         # Table 5          -> clean_mask.npy
python 03_subgroup_leakage.py # Tables 7, 8      (requires clean_mask.npy from step 02)
```

Run them in order: `03` consumes the near-duplicate mask written by `02`. Random state
42 is fixed throughout, so the output is deterministic.

### 2. Re-run model training (`training/`)

```bash
# Train classical baselines (TF-IDF + SVC, MultinomialNB) and fine-tune
# mBERT, XLM-RoBERTa, MuRIL, and IndicBERT (requires CUDA GPU for full transformer run)
python training/train_models.py

# Standalone IndicBERT run with interactive Hugging Face Hub authentication
# (ai4bharat/indic-bert is a gated model requiring Hugging Face access approval)
python training/train_indicbert.py
```

## What each script produces

### `training/`

- **`train_models.py`** — validates the stratified 80:10:10 corpus, fits a 5,000-feature
  `TfidfVectorizer` strictly on `train` for linear `SVC` and `MultinomialNB`, and
  fine-tunes four Hugging Face transformers (`bert-base-multilingual-cased`,
  `xlm-roberta-base`, `google/muril-base-cased`, `ai4bharat/indic-bert`) for 3 epochs
  (`lr=2e-5`, `weight_decay=0.01`, `max_length=128`, `train_batch_size=16`,
  `eval_batch_size=32`, `fp16=True`, best checkpoint selected on development `macro_f1`).
  Outputs summary tables and `data/test_set_model_predictions.csv`.
- **`train_indicbert.py`** — authenticates with `huggingface_hub.login()` to access the
  gated `ai4bharat/indic-bert` checkpoint and runs the 3-epoch IndicBERT training and
  test-set evaluation under the identical hyperparameter configuration.

### `analysis/`

**`00_audit.py`** — corpus statistics, the 80/10/10 split balance, exact-duplicate and
cross-partition overlap checks, the character 5-gram near-duplicate audit at Jaccard
0.7/0.8/0.9, and a check that emoji survive preprocessing as shortcode text.

**`01_benchmark.py`** — fits the reference linear SVC of Section 5.2.1 under the exact
published configuration, derives the keyword lexicon from the training partition,
**selects the lexicon size on the development partition**, then scores all seven systems
once on the test partition. Produces:

- Table 3, the benchmark with 95% paired bootstrap confidence intervals
- Table 4, the lexicon-size sweep with both the development and test columns
- Table 6, all 21 pairwise comparisons with Holm-adjusted McNemar values
- the full 25-term development-selected lexicon

The bootstrap draws one shared set of 1,000 resample indices and reuses it across all
systems, which is what makes the interval on the *difference* between two systems valid.

**`02_ablation.py`** — the `dhoti` prevalence figures with all three denominators
(corpus, train, test), and the four-condition ablation of Table 5: R0 reference, R1
masking, R2 removal, R3 population control. The decomposition it prints separates the
effect of the term from the effect of changing the evaluated population. Writes
`clean_mask.npy`.

**`03_subgroup_leakage.py`** — Table 8, the leakage-controlled re-evaluation on the
Jaccard < 0.8 subset; Table 7, recall on offensive comments by named target group; and
the error-overlap statistics (mBERT vs. lexicon Jaccard, oracle ceiling, majority vote).

**`stat_reliability.py`** — a standalone CLI version of the reliability procedure, usable
on any prediction file with a `y_true` column plus one column per system:

```bash
python stat_reliability.py predictions.csv --out results
```

## `exploratory/`

Not reported in the paper, kept for provenance:

- `run_experiments.py`, `diagnostics.py` — the keyword-saturation and single-term
  analyses as first explored, including the lexicon-size sweep scored on test. The paper
  reports the development-selected version in `01_benchmark.py` instead.
- `final_analysis.py` — a combined pass over all seven systems, superseded by the
  `analysis/` scripts.
- `nepsense_keyword.py` — replication of the keyword-saturation test on the NepSense
  Devanagari corpus. Needs `NepSense_Data_Version_1.xlsx` in `data/`. Note the
  Devanagari-aware `token_pattern` at the top: scikit-learn's default `\w\w+` treats
  Devanagari vowel signs as token boundaries and shatters every word, costing roughly
  0.20 macro F1. Any Devanagari text pipeline using the default is affected.

## `manuscript/`

- `mkeq2.py` — renders the nine display equations as typeset PNGs, stacking multi-part
  equations so they fit a two-column measure. Run before the builder.
- `build_cys2.py` — builds the two-column CyS `.docx` from `revised.md` plus the CyS
  template. Converts author–year citations to the template's numeric style, numbers
  references by first appearance, places wide tables in full-width single-column islands
  via continuous section breaks, and sizes equations and figures to the column.

Both expect to run from a directory containing `revised.md`, the unpacked template in
`tpl/`, `eq2/`, and `media/`. They are included for reproducibility of the submitted
document rather than as general-purpose tools.

## Requirements

Python 3.9+. See `requirements.txt`. The manuscript scripts additionally need
`matplotlib`, `pillow`, and `pandoc` on the path.
